# Clinic Booking

Version 1 · 2026-10-20

## Goal

Patients of a small clinic book visits online, and the front desk runs each clinician's day: books visits for callers, moves and cancels them, and sets weekly hours.

It leaves out reminders, payments, insurance, video visits, patient accounts, and clinics with more than one location.

## Constraints

* TypeScript throughout: Node.js with Express, React for the two web apps, PostgreSQL through Prisma.
* One container service and a managed database on AWS. One deployable service, no microservices.
* One deployment serves every clinic. Each clinic has its own subdomain, like `harbor.clinicbook.app`, and every record belongs to one clinic.
* About 40 clinics at launch, each with 2 to 8 clinicians and up to 150 visits a day.
* Two engineers. The first clinics go live in January.
* Our team sets up each clinic and its clinicians at onboarding, so there are no screens for that yet.
* Assumption: a visit is 15 to 60 minutes long and starts on a quarter hour.

## Modules

### Front desk app

* **Does:** Shows each clinician's day. Staff book visits for callers, move and cancel visits, and set clinicians' weekly hours.
* **Depends on:** Web API, over HTTP.
* **Code:** `web/front-desk/`

### Booking page

* **Does:** Lets a patient pick a clinician and a free slot, enter their name and phone or email, and book.
* **Depends on:** Web API, over HTTP.
* **Code:** `web/booking-page/`

### Web API

* **Does:** Serves both apps over HTTP. Finds the clinic from the subdomain, checks staff sign-in on front desk routes, and turns each request into one call to a module. Holds no business rules.
* **Depends on:** `Bookings`, `PatientDirectory`.
* **Code:** `src/api/`

### Booking

* **Does:** Creates, moves, and cancels visits. Rejects a visit that overlaps another one for the same clinician, with a database constraint catching two made at once, or falls outside the clinician's weekly hours. Keeps each clinic's clinicians and their weekly hours, in the clinic's local time. Lists free slots and a clinician's visits for a day.
* **Owns:** visits, clinicians, and weekly hours.
* **Depends on:** `BookingStore`, `Clock`.
* **Code:** `src/booking/`

### Patients

* **Does:** Keeps each patient's name, phone, and email. Finds a returning patient by phone or email, so booking again doesn't create a duplicate.
* **Owns:** patients.
* **Depends on:** `PatientStore`.
* **Code:** `src/patients/`

## Interfaces

```ts
// Shared types
type LocalDate = string; // "2026-11-03", in the clinic's time zone
type TimeRange = { start: Date; end: Date }; // UTC
type Slot = { clinicianId: string; start: Date; end: Date };
type Visit = {
  id: string;
  clinicId: string;
  clinicianId: string;
  patientId: string;
  start: Date;
  end: Date;
  reason?: string;
};
type Clinician = { id: string; clinicId: string; name: string };
type Day = "mon" | "tue" | "wed" | "thu" | "fri" | "sat" | "sun";
type WeeklyHours = Record<Day, { from: string; to: string }[]>; // "09:00", in the clinic's time zone

class SlotTaken extends Error {}
class OutsideWeeklyHours extends Error {}
class VisitNotFound extends Error {}

// Booking, used by the Web API
interface Bookings {
  clinicians(clinicId: string): Promise<Clinician[]>;
  weeklyHours(clinicianId: string): Promise<WeeklyHours>;
  setWeeklyHours(clinicianId: string, hours: WeeklyHours): Promise<void>;
  freeSlots(clinicianId: string, date: LocalDate, minutes: number): Promise<Slot[]>;
  book(slot: Slot, patientId: string, reason?: string): Promise<Visit>; // SlotTaken, OutsideWeeklyHours
  move(visitId: string, to: Slot): Promise<Visit>; // SlotTaken, OutsideWeeklyHours, VisitNotFound
  cancel(visitId: string): Promise<void>; // VisitNotFound
  day(clinicianId: string, date: LocalDate): Promise<Visit[]>;
}

// Patients, used by the Web API
type Patient = { id: string; clinicId: string; name: string; phone?: string; email?: string };

interface PatientDirectory {
  findOrCreate(clinicId: string, details: { name: string; phone?: string; email?: string }): Promise<Patient>;
}

// Stores: each owned by the module that uses it. src/db/ implements them with Prisma.
interface BookingStore {
  getVisit(visitId: string): Promise<Visit | null>;
  visitsForDay(clinicianId: string, range: TimeRange): Promise<Visit[]>;
  saveVisit(visit: Visit): Promise<void>; // SlotTaken when the database catches an overlap
  removeVisit(visitId: string): Promise<void>;
  clinicians(clinicId: string): Promise<Clinician[]>;
  weeklyHours(clinicianId: string): Promise<WeeklyHours>;
  saveWeeklyHours(clinicianId: string, hours: WeeklyHours): Promise<void>;
}

interface PatientStore {
  get(patientId: string): Promise<Patient | null>;
  findByContact(clinicId: string, phone?: string, email?: string): Promise<Patient | null>;
  save(patient: Patient): Promise<void>;
}

interface Clock {
  now(): Date;
}
```

## Key flows

### A patient books a visit

1. The booking page asks the Web API for free slots. The Web API calls `Bookings.freeSlots`. Booking takes the clinician's weekly hours for that day and takes out the visits already booked.
2. The patient picks a slot and enters their details. The Web API calls `PatientDirectory.findOrCreate`, then `Bookings.book`.
3. Booking checks the slot against weekly hours and other visits, and saves it with `BookingStore.saveVisit`. If someone else took the slot a moment earlier, the database rejects it, and the patient sees `SlotTaken` and picks again.

### The front desk moves or cancels a visit

1. Staff drag the visit to a new time in the front desk app, or cancel it. The Web API calls `Bookings.move` or `Bookings.cancel`.
2. A move goes through the same checks as a new booking.

## Decisions

### One service, one folder per module

It's the house rule, and two engineers can't run more. Modules call each other only through the interfaces above, so one could become its own service later without changing its callers. Not chosen: separate services for booking and the web API.

### Each module owns its store interface

`src/db/` implements `BookingStore` and `PatientStore` with Prisma. Business logic never imports Prisma, and tests use in-memory stores. Not chosen: one shared repository layer.

## Open questions

### Reminders

Clinics lose about one visit in ten to no-shows, and reminders are the usual fix. Left out of v1 until we know whether clinics want text or email.

### Patients moving their own visits

Today they call the front desk. Doing it online needs a way for patients to prove who they are, so it waits until clinics ask for it.

### Hours that change from week to week

Assumed each clinician keeps the same weekly hours. Time off and one-off changes aren't covered yet.
