# Set Me Up

Make this project mine through a short Q&A. Ask these one at a time, and wait for each answer before asking the next. Keep each question to a sentence or two, with a quick example if it helps.

1. **What do you do?** Your role, and the kind of software you build, like web apps, backend services, or mobile apps.
2. **What do you usually build with?** Languages, frameworks, databases, and where it runs. "It depends on the project" is fine.
3. **Any rules your designs follow?** Like an architecture style your team uses, tools you can't use, or how you name things.
4. **What language should design docs be in?**
5. **What do you want to design first?** What it does, who uses it, and the few things they do most. "Nothing yet" is fine.

If my setup message already answers some of these, skip them.

Then, in one go:

* Rewrite [profile.md](../context/profile.md) from my answers, in my words, under its headings. Drop the example content. Keep it short and specific.
* Delete the example system, the whole `systems/clinic-booking/` folder. It was written for the example setup.
* If I named a system, design it as in step 1 of [design.md](design.md): make its folder and write version 1. In the dashboard's data, replace the example with it and leave out `example`, as in [maintain.md](maintain.md). If I didn't name one, empty the list of systems in the dashboard's data and leave out `example`.
* Tell me it's done in a few sentences. If you designed a system, tell me the design as in step 1 of design.md, link `architecture.md`, and tell me the dashboard, `index.html`, draws it as a diagram. Then say what I can do next: push back on any part, ask "What if we add …?", or say "Check the design." If I didn't name a system, ask what I want to design first.
